# Монтаж в облаке

Этот репозиторий запускают с телефона через приложение Claude (вкладка Code). Пользователь присылает ссылку на видео и пишет, каким скиллом монтировать. Скиллы лежат в `.claude/skills/`.

Пользователь не программист. Пиши по-русски, коротко и просто, код не показывай.

## Порядок работы
1. **Скачай видео.** Ссылка Google Drive → `gdown --fuzzy "<ссылка>" -O 01_исходники/`. Файл, прикреплённый в чат, тоже скопируй в `01_исходники/`. Если gdown пишет про доступ — попроси пользователя открыть файл «Все, у кого есть ссылка». Несколько ссылок — скачай все.
2. **Монтируй по скиллу**, который назвал пользователь. Папку проекта создавай в `work/<имя-ролика>/`, шаблон скилла копируй туда. Голос, музыку и звуки пользователя клади в `02_звук/<тема>/`, его шрифты, картинки, вставки и иконки — в `03_ресурсы/`. Правила папок и имён файлов — в README. Если скилл не назван — спроси, какой.
3. **Отличия облака от компьютера** (правила скиллов про это не знают):
   - Это Linux: Python — `python3`, Chrome — `/usr/bin/google-chrome`. Если `.venv` нет, используй системный `python3` — пакеты уже стоят.
   - Видеокарты нет: распознавание идёт на процессоре, это нормально. Не запускай несколько рендеров одновременно.
   - Показать кадры на экране нельзя. Где скилл просит «покажи лист кадров и дождись ок» — пришли 1–2 кадра картинкой в чат, если можешь; если нет — опиши словами и продолжай, не жди подтверждения, если пользователь не просил.
   - Рендер через Chrome на нескольких вкладках сразу: бери `/opt/pw-browsers/chromium_headless_shell` (`headless: 'shell'`, `--no-sandbox`), обычный Chrome здесь зависает. В `clean-premium` это уже сделано.
   - Модель распознавания `sherpa-onnx-zipformer-ru-2024-09-18` уже лежит в `~/models` (её качает setup.sh). В папке проекта сделай ссылку `ln -s ~/models models`. Если её нет — скачай: github.com/k2-fsa/sherpa-onnx → releases → asr-models.
   - CapCut здесь нет. Скилл `capcut-effects` вставляет эффекты в проект CapCut — в облаке его доделать нельзя, предложи пользователю запустить его на компьютере. `shorts` рассчитан на видеокарту и Windows: здесь работай на процессоре, вместо `export.ps1` — ffmpeg.
4. **Сдай результат.**
   - Готовое видео — в `04_рендер/<тема>/<дата>_<тема>_<вариант>.mp4` (например `04_рендер/важность/2026-11-20_важность_силуэты.mp4`), без пробелов, версии `_v2`. Файл должен быть **меньше 90 МБ** (лимит GitHub 100 МБ): если больше — пережми `ffmpeg -crf 23…28 -preset slow`, звук `aac 160k`.
   - Добавь в git только `04_рендер/` (и новые файлы в `02_звук/`, `03_ресурсы/`, если они меньше 90 МБ), закоммить, запушь в свою ветку. `work/` и `01_исходники/` не коммить.
   - В ответе напиши: что сделано, имя файла, название ветки, и как скачать: на GitHub открой репозиторий → переключи ветку → папка `04_рендер` → файл → «Download raw file».
